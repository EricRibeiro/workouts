Scope: `Packages/WorkoutsKit/Sources` (engine, sets/blocks/supersets, rest timer, templates and drafts, history stats,
records/PRs, units) and how `Workouts/` calls into them. Read-only; no code was changed and no simulator was used.

## Verdict

No P0 or P1. The engine's core paths hold up: every mutation saves, structural edits roll back and keep typed values,
Finish/Discard are atomic, Previous and plan lookups are by n-th row and by set kind, the rest timer is an end date
(never a counter) with consistent adjust/extend/skip/expiry rules, PRs are strictly-before and "equal is not a PR", and the
Monday-first week math is cut in the calendar's time zone (DST-safe through `Calendar` arithmetic). One P2 breaks the
"supersets are contiguous" invariant the rest of the engine relies on.

## Nits and out of scope

- **Hardening (CloudKit-adjacent, PLAN 8):** `Dictionary(uniqueKeysWithValues:)` traps on a duplicate id at
  `TemplateDraft.swift:194, 417, 440` and `PastWorkoutDraft.swift:156, 227, 244`. Nothing creates duplicate ids today, but
  the schema has no `.unique` (by design), so a CloudKit merge or a hand-edited import could; the engine already uses
  `uniquingKeysWith`. Switch these to `uniquingKeysWith: { first, _ in first }`.
- `SetInputFormat.parseWeight` (`SetInputFormat.swift:58`) returns nil above 10,000, and nil means "clear the field": one
  extra digit typed onto `1000` wipes the weight rather than rejecting the keystroke. Worth checking against the field's
  handling; harmless if the field keeps the previous text.
- `RecordTracker` / `prsInSession`: an exercise's first ever session reports every record it can (e1RM, heaviest, volume,
  duration). That is the spec (`data-model.md`), but it means every new exercise shows up in Recent PRs. Eric's taste.
- **Timed exercises are only ever inferred from data** (`TemplateDraft.swift` `isTimed: false` on add,
  `ActiveWorkoutEngine.isTimed`): a plank added fresh, with no history or template duration, gets a Reps column and there
  is no way to log seconds. The web derives it the same way, so this is parity, not a regression; whether a per-exercise
  "timed" flag is wanted is Eric's call.
- `ActiveWorkoutEngine.finish` docstring: "A running rest is cleared.Returns" (missing space), line 452.
