## Round-3 fixes: verified

- **finish(.complete) filledValues** (ActiveWorkoutEngine.swift:496-503): it uses the same fill as `check(_:)`. If the save fails, `rollbackKeepingEdits` puts back the typed values (pendingEdits) and drops the filled ones, which is correct. It still keys on `hasValues(set)` (typed values only), so a set with nothing typed is dropped as before. That matches the test and the Finish dialog's counts. One ordering concern is listed as K4-1.
- **Gregorian bucketing** (`gregorian(like:)`, WeeklyCounts.swift:17): `mondayFirst` wraps it. HistoryList.monthStart/dateText, ChartRange.start, the HistoryDashboard week sums and the CalendarMonth grid/shift all go through it. `CalendarMonth.day(of:)` still uses the caller's calendar. That is consistent, because the grid dates and the workout dates both go through that same function, so the keys match. No gap.
- **SetKeyboard.stepped placeholder** (SetKeyboard.swift:61-79): an empty or whitespace-only cell steps from the placeholder. A "–" placeholder parses to nil and the base becomes 0. The time placeholder is raw seconds (`placeholder(count:)` in SetTableSources), so `parseCount` reads it. Both call sites pass the right placeholder for the column (SetTable.swift:396, SetRow.swift:215/242). Correct.
- **HealthEnrichmentRun earliest-date backfill** (HealthEnrichmentRun.swift:90-105, 249-258): the predicate `startedAt >= earliest` matches `process`'s own filter (line 125). The cheap `fetchCount` early-out still runs first. Correct.
- **resetUnmatched / clearAll snapshot restore** (lines 204-243): the snapshot covers all 14 fields that `clearHealth()` touches (WorkoutHealthFields.swift:99-151). The restore puts back the persisted values, so a later unrelated save writes the same values and does no harm. Correct.
- **HeartRateSeries.clippedToStart**: handles empty input, all samples before the start, a sample exactly at 0 (no duplicate is inserted) and unsorted input. Correct. One display nit is listed as K4-2.
- **FoldPlacement.columnWidths minimum gutter**: the gutter widens symmetrically up to `spacing`. If a side is narrower than `minimumColumn` it falls back to an even split. A negative `total - spacing` gives zero-width columns rather than negative ones. Correct.
- **RemoteChangeObserver clock injection**: the behaviour is the same as before, with the clock captured before the Task. Correct. A test-seam nit is listed as K4-3.

| K4-1 | P3 | Session/ActiveWorkoutEngine.swift:494-509 | `finish(.complete)` fills and deletes in one pass. `filledValues` → `previous(for:)` / `plan(for:)` find a set's position from the live `row.sets` and `workout.exercises` (`indexByKind`, nth row of the exercise). Earlier sets and rows of the same exercise may already have been `context.delete`d in that same loop. If SwiftData drops a deleted model from the relationship array before save, the later set shifts index. Example: set 1 is empty and dropped, set 2 has only reps typed. Set 2 would then take Previous set 1's weight instead of set 2's, so it is filled with a value other than the greyed placeholder the user saw. Today this is probably safe: `removeSet` filters `!== set` defensively, which suggests the array keeps deleted models until save. Still, the result depends on SwiftData's timing, and no test puts the dropped set before the filled one. | Compute `filledValues` for every set first (a pre-pass over all rows), then apply the fills and deletions.
