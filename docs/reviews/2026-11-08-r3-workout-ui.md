# Review round 3: active workout UI (cover, finish flow, template dialog, SetTable)

Scope read: `Workouts/Features/ActiveWorkout/{ActiveWorkoutCover,BenchArrangement,ExercisePane,FinishFlow,FinishSummaryView,TemplateUpdateDialog}.swift`, every file in `Workouts/Features/Shared/SetTable/`, the finish, template-update and commit wiring in `Workouts/App/RootView.swift`, plus the engine paths they call (`ActiveWorkoutEngine.swift` setValues/commitEdits/check/removeSet/finish/discard, `+Superset`, `+BlockEdits`, `SetKeyboard.stepped`).

Paths I checked end to end that hold up, so nothing is reported for them:
- Typed values going into the model on every keystroke, with commits on focus change, minimise, inactive and on every engine mutation. Finish, Discard or Check while a cell still has focus loses nothing.
- Check dismissing the keyboard, and a refused check with its wiggle.
- Deleting a focused row.
- Fold and rotation. There is one ArrangementView/BenchLayout tree, the pane is a conditional secondary, and only `onSelectExercise` changes, so the table identity, focus and scroll survive. The info sheet is cleared on the switch to regular width.
- Rolling back when finish or discard fails.
- The template-update prompt after the summary closes.
- Superset sheet: Save is enabled only with 2 or more blocks.
- The frozen last frame shown during dismissal.
