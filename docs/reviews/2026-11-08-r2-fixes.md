## Verified (no finding)

- **`reloadAfterRemoteChange` (P-01).** It asks the store by `persistentModelID` instead of trusting the model. The tests mutate through a second `ModelContext` on the same container, as a CloudKit merge does. Before the fix, `deletedRunningWorkoutIsDroppedByTheRemoteChangeHandler` and `workoutFinishedElsewhere…` would fail, because `reloadPrevious` kept `engine.workout`. `activeWorkout()` now goes through `liveWorkout`, so mutations refuse deleted models.
- **P-04 predicates.** `$0.workout?.finishedAt != nil` and `$0.workout?.id != id` on the optional relationship are correct: a row with no workout yields `nil != id` (true), but `finishedAt != nil` excludes it. `Set.contains` translates, and the kit's Previous and Finish tests pass on the new fetch. The `loadPrevious` semantics are kept: newest workout with a completed set wins, rows by position. Except for R2-03.
- **`PastWorkoutDraft` (E-06/08/09).** It now loads only completed sets, and Save deletes the unchecked ones. That matches Finish, and a rename can no longer complete a planned 405. `setDurationMinutes` restores the original seconds on its minute, so `durationChanged` stays false and Health is not cleared. The `completedAt` clamp uses the local `endedAt`, which is the original length when the duration did not change.
- **Volume helpers (E-04).** `volumeKg` and `displayedVolume` are used by the History row, the workout detail and Finish. Assisted volume is 0 in `volumeKg` (the engine's extra guard is redundant but harmless). `chartSeries` and `Summary` still round per session, which is correct for a single session.
- **RestNotifier.** The fire date is computed inside the queue block (the test `aQueueDelayDoesNotShiftTheFireDate` fails on the old code), the interval is clamped to at least 1 s, and both completion handlers run on the main actor after `respond(to:)`.
- **SetRow/SetTable VoiceOver.** "Delete set" moved to the focusable kind and check buttons. Move up/down is offered only where it is possible and goes through the same `source.reorder` as a drag (`SetTableLayout.moved` has tests). The step labels are tested in `SetKeyboardTests`.
- **Importer `completedOnly` (E-06).** It drops unchecked sets and then empty exercises, renumbers, dissolves a superset left with one exercise, and clears `restEndsAt`/`restSetID`. The test covers checked plus unchecked. Except for R2-04.
