## `dev` sim_reset_ui and the lock model

- `run_tests` calls `sim_reset_ui "$SIM_UDID"` (`dev:230`). Every caller (`test`, `ui-test`, `tree`, `check`) is
  dispatched through `sim_guarded` (`dev:1373-1397`), which holds that simulator's lock first (`dev:929`). `ui_shard`
  (`dev:458`) resets only the members of `UI_SIMS`, and each of those is the guarded sim or was taken with `sim_grab`
  (`ui_pick_sims`, `dev:410-423`). The boot falls inside the crash guard's `since` window.
- **No `dev` path boots or resets a simulator it does not hold.** The reaper and heal paths are unchanged and still skip
  held or locked sims.
- Side effects worth knowing are listed as P2-B and P3-D/E below.

## P2

### P2-A `testRestIsForgottenOnAPushedScreenWhileMinimised` cannot fail on the pre-A3-1 code, and it reintroduced the launch race P2-2 removed
`WorkoutsUITests/ResumeControlUITests.swift:73-108`.

- **Why it cannot fail.** The test launches with `-sampleRestSeconds 6`, pushes a past workout, sleeps a fixed
  `Thread.sleep(12)` (line 97), goes back, then asserts the resume ring's label ends in "elapsed".
  - `RestAccessibility.resumeState` (`RestAccessibility.swift:16-23`) reads "rest over" for as long as `endsAt` is
    non-nil, so on its face the check could catch a rest that was never forgotten.
  - It does not. On the old code the ring-bearing root's watcher (`restExpiryWatcher`) starts again when the root
    reappears. `awaitRestExpiry` (`RestExpiryWatcher.swift:55-64`) is then handed an `endsAt` and `forgetAt` that are
    both already past, so it calls `tickRest()` on its first pass and the label flips to "… elapsed" within a frame.
  - `ring.waitForExistence` then reads a label that is already "elapsed". The test passes whether or not anything forgot
    the rest while the detail was pushed.
- **Second problem.** The rest still starts at launch on the wall clock, the pattern P2-2 replaced. Line 82's
  `contains("rest ")` also matches "rest over", so a slow launch is not caught either.
- **Deterministic observable.** Give the DEBUG seam (`Workouts/Debug/RestExpirySeam.swift`) a read side. Under
  `-uiTesting`, add a zero-size accessibility element to the root overlay that is present on every pushed screen:
  identifier `debug.restState`, value `none` / `running` / `over`, derived from `engine.restTimer` (`endsAt == nil` →
  none; past → over).
- **Test change.**
  1. Launch with `-sampleNoRest`.
  2. Start a 60 s rest from the cover ring (as the first test in the file does), minimise, and push the History detail.
  3. Call `app.expireRestNow()`.
  4. While still on the pushed screen, wait for `value == 'over'`, then for `value == 'none'` (timeout of about 3 s
     grace + 5).
  5. Only then go back and keep the existing "elapsed" check.
- **Result.** The old code stays at `over` on the pushed screen and fails deterministically. The `Thread.sleep(12)` goes
  away.

### P2-B The documented Dynamic Type / dark recipe (`xcrun simctl ui booted …`) can change another agent's held simulator, and `dev` now leaves more sims booted
`.claude/skills/verify-ui/SKILL.md:17-18,51-52`, `.claude/skills/design-review/SKILL.md:24-25`, `AGENTS.md:108`.

- **The problem.** `booted` resolves to an arbitrary booted device. `sim_reset_ui` now boots every test simulator
  headless (`dev:215-216`), up to 3 shards per full run. So while a ui-test runs, an agent following verify-ui can switch
  a shard's sim to dark or AX3. The shard is protected by its launch arguments, but a concurrent `./dev test` on that sim
  runs its hosted snapshots at the wrong size.
- **What the agent sees.** Its own `./dev shot` proof comes out at the default appearance. The setting landed on the
  other sim, so the "dark" screenshot is silently light.
- **Scope.** This is the one path in the facet that changes a simulator the caller does not hold, and `dev` has nothing
  between that path and the lock.
- **Fix.** Replace `booted` with the checkout's simulator, e.g. ``xcrun simctl ui "$(cat .build/dev-sim-udid)" …``.
  Better, add a `./dev ui-env <appearance> <size>` that runs under `sim_guarded`, and point all three docs at it. The
  design-review skill's "reset to `medium` after" should also say `large`: `dev` resets to `large`, and `medium` leaves
  a pool sim off the pinned size.

## P3 (round-3 P3s re-checked: all still open, none is really P2)

- **P3-1 (open)** Hand-rolled sleep polls:

    not asserted.

- **P3-2 (open)** `XCTAssertFalse(x.waitForExistence(timeout: 2))` right after a dismiss:

  - Same pattern at `RestRingUITests.swift:148`, `OpenWorkoutURLUITests.swift:66,149`.

- **P3-3 (open)** Unanchored absence checks:
  - `ExerciseDetailUITests.swift:22` checks `exerciseDetail.edit.exists` the instant the name appears.
  - `HealthEnrichmentUITests.swift:30` gives a wrongly triggered lookup 5 s, then calls it absent.
  - `HealthEnrichmentUITests.swift:35` checks `settings.health.enabled.exists` after three swipes with no anchor.
  - Each could false-pass only if the regression is slow to render, so not P2. Use `assertStaysAbsent` or a
    lookup-count debug value.
- **P3-4 (open)** Fixed 3 s settle for the loaded snapshot frame. Still at `SnapshotExerciseDetailTests.swift:39` and
  `SnapshotWorkoutDetailTests.swift:43`. It can only false-fail under load. Not P2.
- **P3-5 (open)** Set-row snapshot gaps:
  - `SnapshotSetRowTests.swift:15` still takes `prefix(7)`, which drops the `canCheck: false` row.
  - No row in the batch has `showsCheck: false` or `showsWeight: false`, and there is no checked warm-up or checked
    duration row.
  - `ExerciseDetail`/`WorkoutDetail` snapshots render only the large-light variant.
- **P3-D `sim_reset_ui` waits on `simctl bootstatus -b` with no bound** (`dev:216`).
  - A wedged boot now hangs inside dev while it holds the sim lock. Before, xcodebuild's own boot timeout applied.
  - Other agents wait up to 30 min (`dev:799`) and then die.
  - Fix: bound it, e.g. a background bootstatus with a deadline, or `timeout`-style kill after about 120 s with a
    message.
- **P3-E `sim_reset_ui` silently undoes an agent's own Dynamic Type / dark setting.**
  - A verify-ui sequence of `simctl ui … content_size accessibility-extra-large` → `./dev tree <Name>` (or `./dev test`)
    → `./dev shot` ends up at Large/Light with no message.
  - The same applies to a claimed sim that `ui_pick_sims`' second pass borrows once it has been idle.
  - Fix: print one stderr line when the reset changes a value (read the current value with `simctl ui <udid>
    content_size` first), and mention the reset in verify-ui.
- **P3-F `.hostedFitting` measures before the trait override applies** (`SnapshotTesting.swift:302` vs `:308`).
  - `controller.sizeThatFits` runs while the controller is still detached, so UIKit-backed content (List/TextField
    cells) is measured at the ambient content-size category. Only the SwiftUI environment is pinned at that point.
  - Under `./dev` the ambient category is now always Large, so the references are stable there. A run from Xcode on a
    sim at another size can still change the fitted height for the AX3 variants.
  - Fix: attach the controller to the overridden window, or set `controller.traitOverrides` too, before measuring.
