## Queued items

### R2-5 (P3, confirmed): FoldColumns reads only active divisions, so the dashboard and workout detail shift on half-fold

- `Workouts/Features/History/DashboardCards.swift:319`: `FoldColumns` uses
  `proxy.reservedRegions(kind: .division).filter(\.isActive)`, while `EvenColumnGrid.swift:42` uses
  `options: .includeInactive`. Flat open (open wide), `FoldColumns` has no division, so `TwoColumnLayout` splits the row
  evenly around 12 pt (`FoldPlacement.columnWidths`, `FoldPlacement.swift` "Two columns"). The row is off the display's
  centre (leading inset plus the trailing bar strip), so the gutter is not on the hinge. When the Duo half-folds, the division
  turns active and both columns jump to the fold. Used by `DashboardColumns` (History, regular width,
  `HistoryView.swift:146-153`) and `WorkoutDetailView.swift:198`.
- **Fix:**
  1. Read `.includeInactive` in `FoldColumns` (`DashboardCards.swift:319`), the same way as `EvenColumnGrid`.
  2. **Required with step 1:** `FoldPlacement.columnWidths` uses the division's own width as the gutter. An inactive hinge
     reports (near) zero width (`foldColumns`' doc comment says so, and that function widens to `spacing` for this reason).
     Without this step the two columns would touch on a flat-open Duo. Widen the gap to at least `spacing` around the
     division's centre, the same way `foldColumns` does:
     `widen = max(0, spacing - (upper - lower)) / 2`, left = `lower - widen`, gap = `max(spacing, upper - lower)`.
  3. Also fall back to the even split when either side would come out narrower than some minimum, not only when
     `upperBound < total`.
  4. Add kit tests: a zero-width division at 400 in 800 gives `(394, 12, 394)`, and a lopsided division gives the even split.
- **Proof:** `./dev kit FoldPlacement`, then `./dev poses` on `WorkoutDetail` and `History`. In open-wide the gutter should sit
  on the hinge, and going to book should move nothing.

### R2-6 (P3, confirmed): a folder header's title and chevron end up on opposite panels at the hinge

- `Workouts/Features/Workout/FolderSection.swift:125-137`: the header label is
  `HStack { Text(name (count)); Spacer(); chevron }` with `.contentShape(Rectangle())`, inside the full-width
  `ScrollView` column (`WorkoutView.swift:194-233`, `.padding(.horizontal)`). In book pose the title is on the left panel,
  the chevron is at the right panel's trailing edge, and the one tap target spans the fold. That breaks "keep each view
  entirely on one side of the division" (duo-layout.md). The "Unfiled (n)" header (`WorkoutView.swift:216-222`) is plain
  leading text and is fine.
- **Fix (no geometry needed, the same in every pose):** put the chevron right after the title and keep it out of a
  full-width hit area:
  - change the label to `HStack(spacing: 6) { Text(...); Image(systemName: "chevron.right")... }`, keeping
    `.frame(minHeight: 44)` and `.contentShape(Rectangle())` on that HStack;
  - then lay the `Menu` out leading with `.frame(maxWidth: .infinity, alignment: .leading)` **outside** the Menu (after
    `.menuStyle`), so the empty trailing space is not part of the button.

  The header then stays in the left column at any width, like the Fitness/Music "Title >" section headers. Optional: if a
  full-width target is wanted on closed/compact, cap the label's width at the fold with `FoldPlacement.columnGap` in
  `.includeInactive` mode. The fixed-size version is simpler and needs no pose-specific code.
- **Proof:** `./dev shot` of `Root` half-open (book) shows the title and chevron together on the left panel.
  `./dev ui-test` on the folder toggle suite (the identifier `workout.folder.<id>.toggle` is unchanged).

## Swept and fine

- No `UIScreen`, idiom or orientation reads anywhere in the app or kit. `onHingeChange` is not used for layout.
- `BenchArrangement.swift`: one fixed tree (primary, secondary, an optional trailing header). It reads only active divisions,
  which matches the system `.split` it reproduces, and the bench header is the last subview, so adding it never re-identifies
  the table. Frames are clamped (`FoldPlacement.frames`).
- `ActiveWorkoutCover` / `TemplateEditor` / `PastWorkoutEditor`: one `ArrangementView` in both widths. The pane is dropped
  only through `axes` and the `if showsPane` secondary, so the table keeps its identity, focus and scroll across
  compact and regular. Unfolding with the info sheet up clears it (`ActiveWorkoutCover.swift:137`).
- `ExerciseDetailView.swift:141`: the pushed detail at regular width is an `ArrangementView` in every pose, and the split
  column variant is a single column (the split view itself sizes to the fold).
- `EvenColumnGrid` + `FoldPlacement.foldColumns`: an even count, the middle gutter on the hinge (inactive included), unequal
  halves handled. History month grids (`HistoryView.swift:184`, R2-2's fix) and the template grids use it.
- Fixed sizes found are caps or minimums on small glyphs (`RestRunningSheet.swift:80` maxWidth 360 ring,
  `minWidth: 24/28/44/72` labels and targets, `HeartRateChart` 8 pt legend dot). The 320 pt split-column minimum in
  `ExercisesView.swift:46` is commented and deliberate. None is a layout width.
- Compact-to-regular state: `WorkoutView.open` chooses sheet or push at the moment of the tap. An open sheet or push
  survives a fold either way, and `ExercisesView` selection is one `@State` shared by both widths.
