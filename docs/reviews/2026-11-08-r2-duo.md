### R2-1 (P2): open wide and closed landscape, the info sheet's medium detent is all hero

The sheet turns the hero cap off (`exerciseHeroCapped = false`, `ExerciseInfoSheet.swift:38`) so the 16:9 media fills the
sheet's width. That suits the 466 pt closed-portrait sheet, but the centred sheet open wide is about 630 pt wide, so the
hero is about 355 pt tall, more than the medium detent. `open-wide.png` shows only the image (upscaled and visibly
soft) with no name and no About/History/Charts/Records segments; closed landscape is the same. The person must drag to
learn which exercise this is. Open tall and closed portrait are fine.

Fix (one worker task): in `ExerciseMediaHeader`, when `exerciseInfoSheetContent` is true, cap the hero to the height that
leaves the name and segmented control visible at the medium detent (for example `min(width * 9/16, containerHeight * 0.5)`
read with `onGeometryChange` on the sheet's container), keeping the uncapped 16:9 width on the closed portrait sheet.
Proof: `./dev poses .build/review-duo-r2/ExerciseInfoSheet -- -preview ExerciseInfoSheet -uiTesting`, where name and segments
are visible in all four poses.

### R2-2 (P2): book pose, History's session rows straddle the fold

The dashboard is two columns with the gutter on the division (D-checked, `half/History.png`), but the month sections below it
are full-width `List` rows: title, date and PR count on the left panel, the disclosure chevron at x ≈ 1635 of 2576 on the
right one. Each row is a single tappable element across the hinge, which duo-layout forbids ("a row that crosses the fold is
on us"). JC58 accepts scrolling through a horizontal (laptop) fold, not a book fold. Fix (one worker task): on regular width,
lay each month's entries as cards in two `FoldColumns` (or the `EvenColumnGrid` with a two-column minimum), as the dashboard
does, keeping the plain `List` on compact. Proof: `./dev run -- -preview History -uiTesting`, then
`./dev fold half-open .build/review-duo-r2/half/History.png` and `./dev pose closed-portrait`.

### R2-3 (P2): thumbnail rows redraw forever, so their screens never settle (root cause of D6)

Reproduced on an otherwise free sim: `poses` fails at the first pose change for Exercises, TemplatePreview and ExercisePicker
(`no two consecutive captures were identical within 10 s`), while PastEditor, ExerciseDetail and the cover (hero only) settle.
The common element is `ExerciseRow`'s thumbnail: a `TimelineView(.animation(minimumInterval: 1/30))` that cross-fades
continuously, with holds of only 0.16 x 2.4 s = 0.38 s at each end. Two identical 2853 px captures 300 ms apart rarely land
inside one hold under load, so the settled proof (and `./dev shot`) is unusable on these three screens; every visible row also
redraws at 30 fps for as long as the list is on screen. Fix (one worker task): freeze the cross-fade to the start frame under
`-uiTesting` (as Reduce Motion already does in `ExerciseRow.swift:116`, a launch flag read once), so pose proofs and UI tests
settle; optionally lengthen the holds. Proof: `./dev poses .build/review-duo-r2/Exercises -- -preview Exercises -uiTesting` exits 0.

### R2-4 (P2): the gallery hosts sheet screens as roots, so their Duo poses prove nothing

Settings, FinishSummary, Calendar, ExercisePicker and CustomExerciseForm are presented as sheets with
`presentationPlacement(.center)` in the app, and JC58 relies on that sheet moving off the fold. The gallery shows them
full-screen instead (`Settings/open-wide.png`: a Form across the hinge with segmented controls split by it), so neither the
placement nor the book-pose behaviour is ever captured. Fix (one worker task): give these gallery entries a host like
`ExerciseInfoSheetDemo` (`PreviewGallery.swift:146`) that presents the view in a `.sheet` with the same detents and
placement as its real caller. Proof: `./dev poses .build/review-duo-r2/Settings -- -preview Settings -uiTesting`, then a
half-open shot of the same.

### R2-5 (P3): two column helpers read the fold differently

`EvenColumnGrid` reads `.includeInactive`, so the Workout tab gutter already sits on the hinge flat open (`Root/open-wide.png`,
cards end about 20 pt left of it). `FoldColumns` (History dashboard, WorkoutDetail) reads only active divisions, so flat
open its gutter is about 25 pt left of the hinge and "Cable Lat Pulldown" starts on it (`WorkoutDetail/open-wide.png`), and the
columns jump when the Duo half-folds. duo-layout: "Pass `.includeInactive` to reserve the space so layouts don't jump when it
activates." JC72 allows flat-open crossing, so this is a consistency nit. Fix: use `.includeInactive` in `FoldColumns` as well.
Proof: `./dev kit FoldPlacement`, then `./dev poses` on WorkoutDetail.

### R2-6 (P3): book pose, a folder header puts its title and its collapse chevron on opposite panels

`half/Root.png`: "Upper Body (2)" on the left, the chevron at the right panel's edge. Same rule as R2-2 for a small target.
Fix: on regular width keep the chevron next to the title (`Spacer` only up to the first column group), or make the header
span only the left column. Proof: Root half-open shot.
