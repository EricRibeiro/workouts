# Round 4 — screens facet (History, Exercises, Workout tab/templates, Settings)

Read-only code review. I checked the round-3 fixes first (`git diff 36e390f..50d3267`), then went over the rest of the facet.

## Round-3 fixes I verified (no regression found)

- **History search scope reset** (HistoryView.swift:85-88): `isPresented` is bound and `onChange` resets `scope = .all` on dismiss. Nothing else in the History feature writes `scope`, so no programmatic path skips the reset.
- **History load-failed + Retry** (HistoryView.swift:117-139, 152-165): a cancelled read is caught by the guard before `loadFailed` is set. A failure with rows already on screen keeps them. Retry bumps `Inputs.attempt`, which restarts the `.task`. The `finished.isEmpty` branch comes first, so an empty store never shows the error.
- **FailLoads** (Debug/FailLoads.swift): the body is `#if DEBUG`. In Release it returns false and never reads the launch argument. `SlowLoads` is DEBUG-gated the same way.
- **ExerciseDetail loadFailed/Retry + placeholder** (ExerciseDetailView.swift:114-132, 208-237): `CancellationError` is guarded. Retry bumps `Fingerprint.retries`. Every embedder that changes `exerciseID` sets `.id(...)`: ExercisePane:31, ExercisesView:137, and the peek sheet is rebuilt for each exercise. So `detail`, `detailLoaded` and `loadFailed` cannot leak from one exercise to the next, even though `Fingerprint` has no exerciseID.
- **WorkoutDetail weight-type reload key** (WorkoutDetailView.swift:139-147, 315): `store.weightTypes` is in the task id and is passed to the reader.
- **CustomExerciseForm deleted-while-editing** (CustomExerciseForm.swift:277-290; kit CustomExerciseForm.swift:212-222): the kit throws `exerciseDeleted` before it mutates anything, and OK dismisses the form. Nothing is created by accident.
- **NoExerciseResultsView** (FilterPillRow.swift:55-73): the filter-specific state shows only when the query is blank and a filter is on. `allowsHitTesting(false)` keeps the pills tappable. Both call sites pass `bodyPart`/`category`.
- **Blank-name disabled buttons** (WorkoutView.swift:140, 154; TemplateEditor.swift:112): uses the same `cleanedName` trimming that the kit's create/rename and `TemplateDraft.rename` apply.
- **sheetSaveErrorHost / editorCovers counter** (SaveErrors.swift:98-107; TemplatePreview.swift:217): the counter is balanced.
  - The sheet is closed only by `previewSheet = nil` or by swipe/Close, and each of those fires `onDisappear` once.
  - Edit-from-sheet opens the editor cover in the sheet's `onDismiss` (WorkoutView.swift:91-103, 344-351), so the counter goes 1 → 0 → 1, never 2.
  - Start-from-sheet presents the workout cover from `onDismiss` too. The root alert is also gated on `isWorkoutCoverPresented`.
  - The pushed (regular-width) preview has no host and uses the root alert, which is correct.
- **TemplatePreviewSheet `presentationPlacement(.center)`**: consistent with the other sheets.
- **EvenColumnGrid ProposedWidth** (EvenColumnGrid.swift:36-55, 79-96): width and fold are measured on the wrapper, which is sized to the proposal, so the feedback loop is gone. The fixed fold columns sum to exactly the measured width (`FoldPlacement.foldColumns`). An unspecified proposal falls back to the ideal width; no call site gives one (List row / vertical ScrollView).
- **FolderHeader chevron** (FolderSection.swift:102-140): the leading frame is outside the Menu, so the hit area hugs the title and chevron and keeps the 44 pt minimum height.
- **FoldColumns / EvenColumnGrid `includeInactive`** (DashboardCards.swift:320, EvenColumnGrid.swift:48): `columnGap` keeps only vertical regions (`width < height`) that lie strictly inside the view. A flat hinge with no width is widened to `spacing` by `columnWidths` / `foldColumns`. A horizontal hinge (open-tall) is ignored. BenchArrangement still filters to `isActive`, but it belongs to the ActiveWorkout facet and is out of scope.
