# Full-app review, round 1b: domain correctness, the remainder (2026-11-07)

Scope: the kit files round 1 (`2026-11-07-r1-engine.md`, E-01..E-04) did not reach: `WorkoutsJSON/Importer` +
`Exporter` (+ the DTOs), `PastWorkoutDraft`, `TemplateUpdate`, `WarmupRamp`, `CalendarMonth`, `WorkoutDetail`,
`ExerciseHistory`, `FolderOperations`, and their app callers (`DataTransfer`, `PastWorkoutEditor`, `RootView` Update
Template prompt, `CalendarSheet`, `WorkoutDetailView`, `ExerciseDetailView`, `WorkoutView`). Read-only. Each finding
marked "confirmed" was reproduced with a scratch Swift Testing test via `./dev kit ZZScratch` (deleted afterwards).

## Verdict

No P0 or P1. Two P2s: one a real data-corruption path in the template update, one a import-to-editor path that turns
planned sets into logged history. Export/import round-trips every stored field; a re-import of a fresh export of a store
with real (sub-millisecond) timestamps skips everything (checked over 200 timestamps: the millisecond encoding never
reads as newer). The calendar grid is Monday-first and DST-safe (`Calendar` arithmetic, `startOfDay` per cell), and
folder ordering/renumbering holds.

## Nits and out of scope

- `Importer`: a template exercise's own `updatedAt` is copied but never compared (children follow the template), while the
  type doc (`Importer.swift:11-13`) lists template and workout exercises among the "strictly newer wins" rows. Doc fix only.
- `Importer` sticky notes (`Importer.swift:188-199`): a document note whose id matches the store's note for exercise X but
  whose exercise is Y moves the note to Y even when Y already has a note, leaving two notes for Y. Needs a hand-edited file.
- `Importer`: a set that gets a fresh id (id collision) leaves the workout's `restSetID` pointing at the old id; and a
  demoted workout keeps `restEndsAt`/`restSetID`. Harmless for a finished workout; clear both when demoting (fold into E-06).
- `Importer` keeps a superset group of one from a file ("the file's own choice", `Importer.swift:589`), while every editor
  dissolves groups of one. `WorkoutDetail.saveAsTemplate` (`WorkoutDetail.swift:351`) also copies `supersetGroup` verbatim,
  so a workout whose superset partner had no completed set yields a template with a one-member superset. Normalize with
  `SupersetGrouping.normalized` in both places.
- `docs/port/data-model.md:101` says the custom `barWeight` is "never converted", but `ActiveWorkoutEngine.setUnit` and
  `TemplateDraft.setUnit` convert it on a unit switch (and `WarmupRamp` relies on that). The code is the better rule; fix the
  spec line.
- `ExerciseHistory.setRows` (`ExerciseHistory.swift:101`) matches a record by exact `==` on the displayed weight;
  `WorkoutDetail.holds` uses a 0.0001 tolerance. Both go through the same `round05`, so no mismatch was found; align for safety.
- `FolderOperations.move(_:to:)` leaves a gap in the old folder's positions (tolerated everywhere; ordering is stable).
- Coverage: every public function in scope has a kit test (`CalendarMonthTests`, `FolderOperationsTests`,
  `TemplateOperationsTests` for duplicate/move, `TemplateUpdateTests`, `WarmupRampTests`, `WorkoutDetailTests`,
  `ExerciseHistoryTests`, `PastWorkoutDraftTests`, `WorkoutsJSON*Tests`, `ImportExportFlowTests`). Gaps are the scenarios
  above: unit switch + Values Only, demoted import with unchecked sets, EZ-kg ramp, shortened past duration. The JSON
  tests' fixtures use whole/quarter seconds only; a sub-millisecond round-trip test (passes today) would guard the encoder.
