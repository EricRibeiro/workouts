### Settled: lb in the History detail vs kg in the past editor — a bug, not taste

The detail is the outlier. The spec says a logged set is shown **as entered, in its own unit**; only aggregates convert:
`docs/port/data-model.md` rule 3 ("Switching a row from lb to kg relabels the numbers, never converts them. Conversion happens
only inside aggregates") and §Units ("A set's own weight in its own unit is reported exactly as entered"); the web's detail
does exactly that (`app/ui/src/features/history/WorkoutDetail.tsx:20-27`, "a set as it was entered, in its own unit (D7)").
The native Exercise detail History segment already follows it (`Packages/WorkoutsKit/Sources/WorkoutsKit/Library/ExerciseHistory.swift:11,108`),
as do the past editor and the active set table. `docs/port/screens/history.md` "Display unit: volume and best sets follow the
unit setting" covers the header volume, the History card's best set and the PR lines, not the per-set lines.

| P | Screen · file:line | What | Fix (one worker task) |
|---|---|---|---|
| P2 | History detail · `Packages/WorkoutsKit/Sources/WorkoutsKit/History/WorkoutDetail.swift:210-214` | `block(...)` formats each completed set with `displayWeight(set, unit: options.displayUnit)`, converting and rounding to 0.5, so a kg session reads "154.5 lb × 8" while the editor, the Exercise History segment and the web read "70 kg × 8" (`.build/review-ui-r2/WorkoutDetail-light.png` vs `.build/review-ui-r2/PastEditor-light.png`). | *local defect*: format the set line with `weight: set.weight, unit: set.unit`; keep `shown = displayWeight(...)` only for `holds(_:set:shownWeight:)` (the PR trophy match), and keep the header volume and PR lines in the display unit. Add a kit test: a kg session with display unit lb shows `70 kg × 8` in `SetLine.text` and its accessibility label, and the trophy still lands on the record set. Proof: `./dev kit WorkoutDetail` then `./dev test SnapshotTests`. |
