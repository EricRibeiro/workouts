## Findings

- **P3: two enabled alerts on one message when a hosted sheet sits over a cover**
  - Where: `Workouts/Features/Shared/ExerciseInfoSheet.swift:79` and `ExercisePickerView.swift:231`, against `ActiveWorkoutCover.swift:156`, `SaveErrors.swift:86` (`EditorCoverHost`) and `TemplatePreview.swift:217`.
  - Cause: only the root's alert stands down through `editorCovers`. The workout cover's `.saveErrorAlert()`, the editor covers' `.saveErrorAlert()` and the TemplatePreview host's alert are always enabled.
  - Scenario: the info sheet is open over the workout cover (or the peek sheet is open over the picker in TemplateEditor), and a save fails. Both alerts' `isPresented` become true. The cover's alert cannot present because a sheet is above it, so SwiftUI logs an "already presenting" warning, and the sheet's alert shows. OK clears the shared message, so both close. In practice this works. It relies on SwiftUI not writing `false` back through the blocked alert's binding; if it did, `acknowledge()` would run and close the visible alert.
  - Fix direction: track nesting depth instead of one count, so only the topmost host enables its alert. One way is for each host to record its depth on appear and enable its alert only while `editorCovers` equals that depth.
- **NIT: a non-numeric `DEV_BOOT_TIMEOUT` aborts**
  - Where: `dev`, `sim_bootstatus`.
  - With `set -u`, a value like `abc` is evaluated in `((i >= limit * 5))` as an unset variable name and aborts the script while the lock is held. The trap then releases the lock. Fix direction: validate with `[[ $limit =~ ^[0-9]+$ ]]` or fall back to 120.
- **NIT: average and max now cover different spans**
  - Where: `HeartRateChart.swift` caption and accessibility label.
  - "Avg" is still the stored whole-workout average, lead-in included, while "Max" is now the plotted peak. Usually invisible, and noted only for consistency.
