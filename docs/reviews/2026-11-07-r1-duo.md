### D1 (P1): the template grid's gutter is not on the fold; a card straddles the hinge

`EvenColumnGrid` derives an even column count from its own width but never reads `reservedRegions`, and its width is the
safe area minus the trailing bar strip, so its centre is not the display's centre. Measured on `Root/open-wide.png`
(951 pt wide, hinge at x = 475.5 pt): four ~200 pt columns, Push 17–215 pt, Pull 228–427 pt, so column 3 spans about
440–640 pt and crosses the hinge. In book pose that column's cards sit across the active division, which DECISIONS
("even column count … so no card straddles the fold; with `.includeInactive` reserved regions the hinge gap widens") and
duo-layout ("Keep each view entirely on one side of the division") forbid. The History dashboard already solves this
(`DashboardColumns` + `FoldPlacement.columnGap`, `DashboardCards.swift:238-294`); the template grid never got the same.

Fix (one worker task): in `EvenColumnGrid`, read the division with `onGeometryChange` +
`reservedRegions(kind: .division, options: .includeInactive)` as `DashboardColumns` does, and when a vertical division lies
inside the grid, split the columns into two equal halves whose middle gutter is the division (`FoldPlacement.columnWidths`
already computes left/gutter/right); add a `FoldPlacement` kit test for an off-centre division. Proof: `./dev kit FoldPlacement`
then `./dev fold half-open .build/review-duo/Root/half-open.png` after `./dev run -- -preview Root -uiTesting`, then
`./dev pose closed-portrait`.

### D2 (P2): the exercise info sheet names no `presentationPlacement` on regular width

DECISIONS ("on regular width every sheet names `presentationPlacement`") is met by every `.sheet` in the app except
`exerciseInfoSheet`. It is reachable on regular width: the template preview's info button (`TemplatePreview.swift:163`)
sets `aboutExerciseID` whether the preview is the compact sheet or the pushed regular-width screen; and in the cover a sheet
opened while closed (`ActiveWorkoutCover.swift:230-231`, compact only) stays up when the Duo opens, now duplicating the
exercise pane beside it.

Fix (one worker task): add `.presentationPlacement(.center)` to the sheet content in `exerciseInfoSheet(exerciseID:)`, and
in `ActiveWorkoutCover` clear `infoExercise` on `onChange(of: horizontalSizeClass)` to `.regular` (the pane takes over, same
exercise via `focusedSectionID`). Proof: `./dev poses .build/review-duo/ExerciseInfoSheet -- -preview ExerciseInfoSheet -uiTesting`.

### D3 (P3): a two-template folder fills only the left half when open wide

With four columns, Upper Body (2) and Lower Body (1) leave the right half of the inner display empty (`Root/open-wide.png`).
Correct by the even-column rule; noted only because D1's fix will change the column geometry anyway. No separate task.

### D4 (P1): the workout detail is one full-width column, so every card crosses the hinge

On regular width `content(_:)` is a single `VStack` of cards (`DetailHeader`, `HeartRateChart`, one `ExerciseBlockView` per
exercise) at the full safe width. On `open-wide.png` the cards span x ≈ 40–2055 px, across the hinge at 1148 px. Nothing
reads the division, so in book pose every card straddles the fold, which breaks duo-layout ("keep each view entirely on one
side of the division"). The wide rows also put "Best Set" and the PR trophies about 1900 px from the set they belong to.
The History dashboard already handles this with `DashboardColumns` (`DashboardCards.swift:238`, used at `HistoryView.swift:143`).

Fix (one worker task): on `horizontalSizeClass == .regular`, lay the detail out with `DashboardColumns`: header and heart-rate
chart lead the left column, and the exercise blocks are dealt across both columns in order (left gets the first ⌈n/2⌉).
Compact stays the single column. Proof: `./dev run -- -preview WorkoutDetail -uiTesting`, then
`./dev fold half-open .build/review-duo/WorkoutDetail/half-open.png` and `./dev pose closed-portrait`.

### D5 (P2): the `ActiveWorkoutCover` gallery entry shows only "No workout in progress"

`-preview ActiveWorkoutCover` hosts the cover on `SampleEnvironment`, which seeds no in-progress workout, so all four PNGs
show the empty state. The logging screen, the most important Duo surface, therefore has no pose proof at all. Also, in book
pose the centred empty-state label (≈ 325–542 pt) would straddle the hinge, though this state is rarely seen. Fix (one worker
task): have the gallery's `.activeWorkoutCover` entry start the sample workout in its container (as `-startSampleWorkout` does
for the app container, `WorkoutsApp.swift:287`) before hosting the cover. Proof:
`./dev poses .build/review-duo/ActiveWorkoutCover -- -preview ActiveWorkoutCover -uiTesting`. Until then, capture with
`./dev poses <dir> -- -uiTesting -startSampleWorkout -openWorkoutCover`.

### D6 (P2): `Exercises` and `TemplatePreview` never settle after a pose change

In round 1, `./dev poses` for both failed with "no two consecutive captures were identical within 10 s". The ExerciseDetail
and TemplateEditor captures, also with media, settled on the same sim. It may have been load (three sharded `ui-test` sims
were running), or something on those screens may keep redrawing after a fold, such as thumbnails reloading in the split's
list. Fix (one worker task): rerun on an idle sim. If it still fails, use `./dev shot --burst` after `./dev fold open` to
find what redraws, and stop it. Not judged as a layout defect yet.

### D7 (P3): open tall, the template editor's block header is inset more than the description

In `open-tall.png` the "Chest, shoulders, triceps." description starts at x ≈ 40 px, but the block name, rest and sticky
band start at about 75 px. The pane below ("Barbell Bench Press", segmented control) is back at 40. Closed and open-wide
align. This is a nit; make the leading inset of the primary's list rows match the header in the stacked split.
