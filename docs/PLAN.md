# Workouts: the native plan

The document Eric and the orchestrating agent (Opus) work from. Written 2026-11-03 by Fable after
the scaffold, the port spec and the `WorkoutsKit` math landed. It is a living file: tick tasks,
record decisions in section 2, never re-litigate what is settled here or in `AGENTS.md`.

Audience note for the orchestrator: read `AGENTS.md` first (toolchain, loop, rules), then this
file's section 6 to find the next unticked task. Each task is sized for one Sonnet worker and names
its proving command. Fable/Opus plans and reviews; Sonnet implements.

## 1. Goal

A private, single-user, native SwiftUI iPhone app that keeps the web app's curated workout-tracking
experience (feature complete, Eric-designed, "awesome") and adds what a PWA cannot do on the
**iPhone Duo**: a real sidebar on the inner display, split layouts, Live Activity + Dynamic Island
for the rest timer, notifications, haptics. Parity is the floor. Not goals: App Store release,
other users, iPad/Mac, widgets, Shortcuts, Control Center, HealthKit/Apple Fitness (Eric starts
his Fitness workouts in Apple's app himself and likes it that way), Apple Watch, the web app.

## 2. Decisions (settled; see `AGENTS.md` → Product decisions for the ones made earlier)

Eric deferred the technical choices to Claude. These close every item in `docs/port/OPEN-QUESTIONS.md`.

**Data and sync**
- SwiftData + CloudKit private database. Container `iCloud.com.ericribeiro.Workouts`. Until the
  Developer Program is approved, the store runs with CloudKit **off** behind one flag
  (`ModelConfiguration(cloudKitDatabase: .none)`); the schema is written CloudKit-safe from day one.
- Settings live in `NSUbiquitousKeyValueStore` (iCloud key-value), not in SwiftData: it is made for
  small preferences, syncs, and cannot produce duplicate rows. Keys: `defaultUnit`,
  `defaultRestSeconds` (90), `weeklyGoal` (3), `e1rmFormula` (epley), `restPresets`,
  `keepScreenOn` (true), `downloadAllVideos` (false). Appearance follows the system (no setting).
- Library: 1,038 exercises bundled as `library.json` + thumbnails, generated by
  `scripts/build-library` from the snapshot (section 4). Seeded on first launch, re-seeded by
  upsert when `libraryVersion` in the JSON is newer than the stored one; never touches custom
  exercises, overrides or sticky notes; retires what left.
- Media: `docs/port/media.md`.
- One-time history migration from the web Postgres: an **Import** action in Settings that reads a
  JSON export (produced later by a script against the web DB) through the normal SwiftData path,
  so it syncs. Exercise ids match because both sides use UUIDv5(source, sourceId); the namespace
  is copied from the web's `store.ExerciseID` when the import script is written (task 7.3).
- Custom exercise: deletable when no history references it, otherwise "Archive" (= retire).

**Navigation and layout**
- `TabView` with `.tabViewStyle(.sidebarAdaptable)`, three tabs: **Workout**, **History**,
  **Exercises** (Workout first and default). Compact → bottom tab bar; regular (open Duo) → sidebar.
  The sidebar carries a **Templates** `TabSection`: one item per folder, templates as children, so
  the inner display gives one-tap access to any template. That is the "full sidebar usage".
- **Settings** is a gear `toolbar` button on the Workout tab (and in the sidebar's bottom) that
  presents a `Form` sheet. No fourth tab.
- Every tab is a `NavigationSplitView`: compact → push; regular → list | detail. Detail on
  compact is a **push**, except the template preview, which stays a medium-detent sheet (that is
  the web's best interaction and it reads well on a phone).
- Templates keep the web's **card grid** on compact (2 columns) and become a 3-column grid when
  regular; folders are collapsible sections.
- Active workout: a full-screen cover on compact. On regular width it takes the detail column of
  the Workout tab with the set table left and an **exercise pane** right (video, instructions,
  Previous, records) — the web's `PLAN.md:204` idea that the PWA could not deliver.
- Minimised workout: `.tabViewBottomAccessory` (the system mini-player slot above the tab bar;
  it adapts to the sidebar) showing name, elapsed time and the rest countdown; tap restores.
- Navigation model `AppNavigation` (@Observable) with typed routes, so Live Activity buttons and
  notification actions can open the logging screen or a template. App Intents exist only as the
  mechanism behind those buttons; nothing is exposed to Shortcuts or Spotlight.

**Active workout behaviour**
- Start from a template or **Empty Workout** (name "Workout"). Exactly one in progress.
- Web rules kept verbatim (`docs/port/screens/active-workout.md`): check → rest starts, presets
  0:30/1:00/2:00/3:00 + up to 6 customs, ±10 s adjust, empty sets cannot be checked, Finish
  dialogs, Discard confirmation, Previous autofill, warm-up ramp, supersets numbering. Superset
  rest starts on every check (web behaviour). No RPE UI (field kept in the model).
- Finish summary adds a **PR count** (native improvement; `prsInSession` already exists).
- Rest end: local notification, interruption level `.timeSensitive`, body "Rest over · Set 3 ·
  27.5 lb × 8" (next set included), actions **Skip** and **+30 s**. In foreground: haptic + flash.
- Timer correctness: store `restEndsAt: Date`, render with `Text(timerInterval:)`; never a counter.
- Keyboard: system `.decimalPad` with an input accessory (−step, +step, Previous, Done); steps
  from the web (`docs/port/screens/active-workout.md`). Custom keypad only if this proves worse.
- `isIdleTimerDisabled` while logging when `keepScreenOn`.

**Native layer**
- **Live Activity** (ActivityKit, widget extension target `WorkoutsLiveActivity`): lock screen +
  Dynamic Island. Compact: exercise glyph + countdown ring. Minimal: countdown. Expanded: exercise,
  "Set 3 of 4", `Text(timerInterval:)`, buttons **Skip** / **+30 s** / **Done set** as
  `Button(intent:)`. Starts on workout start, updates on each check, ends on Finish/Discard.
  Shared `WorkoutActivityAttributes` lives in `WorkoutsKit` (linked by app and extension).
- **Haptics** via `.sensoryFeedback`: set checked `.impact(weight: .light)`, rest end `.success`,
  PR at finish `.levelChange`, destructive confirm `.warning`, minimise/restore `.selection`.
- **Not built, by decision (2026-11-03)**: home/lock-screen widgets, Shortcuts/Siri intents,
  Spotlight, Control Center controls, HealthKit (Eric runs Apple Fitness alongside; a live session
  would need a Watch app anyway).
- **Liquid Glass**: system bars and controls; `.glassEffect()` only for the floating rest pill;
  `.navigationTransition(.zoom)` card → preview, row → detail. Eric's palette becomes semantic
  colours in the asset catalog (accent, ok, danger, warm-up, set-kind colours) with light/dark
  variants; everything else is system material.
- **Accessibility**: every interactive element labelled (agents navigate by the tree too);
  Dynamic Type everywhere, with the set table verified at AX sizes (no clipping; rows may wrap).

**Duo rules (from Apple's app-resizability skill; also in `AGENTS.md`)**
- Size classes only; never `UIScreen.main`, idiom, orientation, or hardcoded sizes. Width can
  change mid-session (fold/unfold) and the app must keep selection, scroll and the active workout.
- Asymmetric safe areas are normal; use `.safeAreaInset`/`.safeAreaPadding`, no magic numbers.
  Observed on Eric's Duo (closed, portrait): the status area is a vertical strip on the trailing
  edge, not a top bar, so trailing-aligned controls sit against it (`docs/port/screenshots/duo-closed-*`).
- All four orientations supported (already in the project). Launch screen generated (already).
- Verify in four poses on the `iPhone Duo` simulator: closed portrait, closed landscape, open
  tall, open wide (`.claude/skills/verify-ui`).

## 3. Experience, screen by screen (what "awesome" means here)

- **Workout tab**: large title, folder sections with the card grid; cards show the exercise
  summary and "last performed" exactly as the web. Tap → preview sheet (medium detent) with Start.
  Open Duo: sidebar lists folders/templates; detail shows the preview with Start; the template
  editor opens in the detail column with the exercise picker as a trailing inspector.
- **Logging screen**: the web's set table (set · previous · weight · reps · ✓) with the native
  keyboard accessory; checked rows tint; rest pill floats bottom-centre as glass; drag down or
  tap the chevron to minimise into the bottom accessory. On the open Duo the right pane follows
  the focused exercise: video loop, instructions, Previous, records, and the sticky note.
- **Rest timer**: pill in app, Dynamic Island when away, notification when locked. Skip/+30 s
  everywhere with the same intents.
- **History tab**: weekly goal chart (Swift Charts) → month sections → cards with best sets and
  PR count; detail with PR lines and trophies; edit past workout; calendar sheet. Open Duo: list |
  detail.
- **Exercises tab**: `.searchable` with body-part and equipment scopes, rows with thumbnail +
  latest best set, custom/retired tags; detail with segmented About / History / Charts / Records,
  video loop at the top, sticky note editable here too (native improvement).
- **Settings sheet**: unit, default rest, weekly goal, e1RM formula, keep screen on, download
  all videos, iCloud status line, Import (migration), About (SmartWorkout credit).

## 4. Architecture

```
Workouts.xcodeproj
├─ Workouts/                 app target (SwiftUI shell + features)
│  ├─ App/                   WorkoutsApp, AppNavigation, ModelContainer setup, Settings store
│  ├─ Design/                Colours (asset catalog), typography helpers, glass rest pill, haptics map
│  ├─ Features/{Workout,ActiveWorkout,History,Exercises,Settings}/   views + view models (@Observable)
│  └─ Resources/Library/     library.json + thumbs/ (generated, committed; ~25 MB)
├─ WorkoutsLiveActivity/     widget extension holding only the Live Activity
├─ Packages/WorkoutsKit/     platform-free: Model (SwiftData @Model types), Math (done),
│                            Library (seed/upsert), Media (MediaStore), Session (ActiveWorkoutEngine,
│                            RestTimer), Activity (WorkoutActivityAttributes)
└─ scripts/build-library     Swift script: snapshot → library.json + thumbs (run on this Mac)
```

- **SwiftData models** (`docs/port/data-model.md`, CloudKit-safe): `Exercise`, `ExerciseOverride`,
  `StickyNote`, `TemplateFolder`, `Template`, `TemplateExercise`, `TemplateSet`, `Workout`,
  `WorkoutExercise`, `WorkoutSet`. All relationships optional with explicit `deleteRule`
  (cascade/nullify; RESTRICT becomes an app check), every stored property defaulted, enums as
  raw strings, `Double` weights, no `.unique`. `LibraryMeta` is a plain `Codable` in `library.json`,
  not a model. `Workout.finishedAt == nil` marks the one in-progress workout; every query
  excludes it (`#Predicate`). Positions are Ints; reorders rewrite them.
- **ActiveWorkoutEngine** (WorkoutsKit, `@Observable`, `@MainActor`): owns the in-progress
  `Workout`, exposes check/uncheck/add/replace/remove/reorder, Previous lookup, warm-up ramp,
  rest timer state, finish/discard. Pure logic tested on macOS with an in-memory
  `ModelContainer`. The app's views and the Live Activity read from it; intents call into it via
  an app-group-shared store (the extension gets a read-only snapshot in `UserDefaults(suiteName:)`
  and sends intents to the app).
- **Entitlements**: iCloud (CloudKit), Push (CloudKit silent), Background Modes
  (remote-notification), App Groups (`group.com.ericribeiro.Workouts`).
  Added with `xcrun xcodeproj`/`AddEntitlement` once a team exists.
- **Testing**: `./dev kit` for all WorkoutsKit logic (SwiftData in memory works on macOS);
  `./dev test` for the few app-level tests (navigation model, settings store); UI proof by
  `RenderPreview` and the device-interaction tools; no snapshot-testing dependency.

## 7. Risks and unknowns

- **Duo fold/hinge APIs**: the simulator's fold switch isn't scriptable here (`verify-ui`); the
  hinge-aware layout APIs named in third-party posts are unverified. Rely on size classes +
  `NavigationSplitView`, and consult Apple's "Preparing your app for iPhone Duo" when a screen
  needs hinge awareness.
- **SwiftData + CloudKit**: no unique constraints, all-optional relationships, schema migrations
  are additive only once CloudKit is on. Keep `SchemaV1` frozen after 7.2.
- **Live Activity on the simulator** works; Dynamic Island rendering needs an Island device
  (`iPhone 18 Pro` sim) for screenshots.
- **Media host dependency**: thumbnails are bundled, so only videos degrade when the server is
  unreachable.
- **TestFlight** needs the paid program; until then everything is simulator-only.
- **Budget**: Fable is expensive; Opus orchestrates from here using this file, Sonnet implements.
